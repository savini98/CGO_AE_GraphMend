# Per-model evaluation harness

This is what C1 and C2 run. For each model it builds the model, runs the
forward pass through a counting backend twice, GraphMend off then on, and
reports the breaks before and after and whether the output changed.

[`artifact/run_break_analysis.sh`](../artifact/run_break_analysis.sh) calls
into this harness, and that is the normal way to run it. Setup and the claim
commands are in [`artifact/README.md`](../artifact/README.md). Use this file
when you want to run a single model, read a row, or add one.

## What is here

```text
paper_eval/
├── registry.py       # the models: how each is built, and what input it gets
├── entry.py          # the measurement program, run under `jac run`
├── run_eval.py       # C1: two arms, break counts and output fingerprints
├── run_fullgraph.py  # C2: torch.compile(fullgraph=True) on both arms
├── run_why.py        # why a given break survived
├── why.py            #   the report it drives
└── _paths.py         # where the patched toolchain and the harness live
```

## Run

`bash scripts/setup.sh` must have been run once. Then, from the repository
root:

```bash
python -m paper_eval.run_eval                          # offline models (default)
python -m paper_eval.run_eval t5-small biogpt          # a subset
python -m paper_eval.run_eval MoLFormer-XL-both10pct   # opt-in, needs network

python -m paper_eval.run_fullgraph                     # C2, all rows
python -m paper_eval.run_why longformer-base-4096 on   # why a break survived
```

No GPU required. The first run of each model is slow: GraphMend recompiles the
imported modeling code through the Jac front end, which is minutes per arm on a
cold cache. Later runs hit the module cache.

## How the two arms differ

GraphMend has no CLI switch. It is controlled by two `jac.toml` keys, and
`run_eval.py` writes a fresh `jac.toml` per arm into a temp working directory:

```toml
[run]
graphmend = true                # on by default
graphmend_claim_imports = true  # opt-in: let GraphMend claim imported .py code
```

Both arms run `entry.py` under `jac run`, which is how the paper describes
using the tool: `jac run model.py`, with no changes to model code. Running it
under plain CPython instead leaves every `[Defer]` rewrite inert, because the
hook that drives it is injected at the `torch.compile(...)` call site and that
only happens in a module Jac compiled.

## Which rule each model exercises

| Model | Rule |
|---|---|
| t5, whisper, bart, blenderbot, opus-mt, biogpt, pegasus, longformer | `[Defer]` |
| Phi-4-mini-instruct, Florence-2, Qwen-Audio-Chat | `[Where]` |
| MoLFormer-XL-both10pct, grounding-dino | `[Trap]` |

Phi-4-mini is the paper's Figure 3 worked example. MoLFormer-XL is its
validation-guard model and is opt-in, since unlike the other rows it needs
network access and `trust_remote_code`; its revision is pinned because `main`
no longer imports under transformers 4.52.4.

To confirm which rule fired, look for the markers GraphMend leaves in the
generated bytecode: `__gm_cond_<n>` for `[Where]`, `__jac_log_emit__` and
`__jac_flush_se_buffer__` for `[Defer]`, and `__jac_tensor_eq_assert__` for
`[Trap]`.

## Reading a row

- **Small configs.** `registry.py` builds most models from a small config, a
  few layers with random weights, so the harness is fast and download-free.
  Graph breaks are structural, so the fix rate and the correctness result carry
  over.
- **Correctness.** Both arms get `torch.manual_seed(0)` so they see identical
  weights. The output tensor is SHA-256 fingerprinted and compared, and the
  input shape is reported per arm so a mismatch is flagged rather than trusted.
- **Not every row should reach 0.** clap-htsat-fused, longformer and
  grounding-dino do not in the paper either. What survives is the paper's
  declared out-of-scope category, so the target for those rows is Table 2's
  percentage, not a clean sweep. Use `run_why` to check that what survives is
  the declared category and not a regression.

## Adding a model

Add a `_build()` returning `(model, inputs)` and a registry entry. Two things
to watch:

- **The code path has to be reachable.** Phi-4-mini only takes the LongRoPE
  branch when `rope_scaling.type == "longrope"` is set. The same applies to
  clap (`enable_fusion`), longformer (sequence length not a multiple of the
  attention window) and Florence-2 (half precision). Miss it and the row passes
  vacuously.
- **`"call": "generate"` measures nothing.** `torch.compile` wraps `forward`
  only, and every other attribute is forwarded to the unwrapped module, so
  `compiled.generate(...)` runs the eager model and records zero graphs.
